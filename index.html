AirlockScratchpad

A secure scratchpad for the developer secrets you're working with right now — one that encrypts them, and forgets them on purpose.

Airlock Scratchpad is not a password manager. Anything that has to outlive the work you're doing today belongs in a real vault — 1Password, Bitwarden, HashiCorp Vault, AWS Secrets Manager. This is the layer above that: somewhere to put the keys and tokens you're actively using, instead of a scratch file.

Getting started

1. Set up the vault

On first launch you create a vault. It's protected by a key held in this Mac's Secure Enclave, unlocked with Touch ID or your login password.

2. Capture a secret

Copy a key from wherever it lives, then press ⌘⇧V. The app works out what it is — a GitHub token, an AWS key, a certificate, a database URL — and opens the matching template with the fields already filled in.

Not ⌘V: that belongs to the system's paste, and taking it would make it impossible to paste into any field in the app itself.

3. Add a recovery code

Settings → Credentials → Generate a recovery code. Print it or write it down. This is the only thing that opens your vault if the Mac is lost, and it is shown exactly once.

Questions

My secret disappeared. Where did it go?

It expired. Everything in Airlock has a deadline — three days by default — because a copy of a secret is not a secret's home. You can change the default in Settings, change it on any individual item, or turn on the Recycle Bin so expired items go there instead of being destroyed.

Why does it ask for Touch ID twice?

Unlocking shows you what you have — names, types, deadlines. Seeing or copying an actual secret asks again. Being in the app is not the same as being allowed to see a credential. After the second unlock there's a grace period, so you won't be prompted repeatedly, but you still press Reveal on each secret you want to see.

I lost my Mac. Can I get my vault back?

Only if you set up a recovery code or a password backup. The Secure Enclave key is bound to that specific Mac and cannot be exported, copied or recovered — not by you, and not by anyone else. There is no server, no account and no reset link.

That's the security model working as designed, and it's why the recovery code exists. Set one up before you need it.

Does it sync between my Macs?

No. There's no sync, no iCloud, no account and no network code of any kind. A secret you need on two machines belongs in a real vault with proper access control.

Can I share a secret with my team?

No, and deliberately so. Shared credentials need access control and an audit trail; building half of that would be worse than not building it, because it invites a use it can't safely support.

The Scrub button didn't find my secret.

Scrubbing is deliberately cautious. It only removes things it's certain about — recognisable vendor tokens, JSON web tokens, passwords inside connection strings, and named assignments that look like credentials. The entropy heuristic alone isn't used, because a git SHA or a base64 blob would trip it, and a scrubber that mangles ordinary log lines is one you'd turn off.

Always read the result before you send it.

Everything from my .env imported as an API Key.

Fixed in a later version. Plain configuration now imports as a Variable, which is visible without a reveal and doesn't get buried among real credentials. Items imported before the fix keep their old type — delete and re-import them, or change the type by hand.

Where is my data stored?

One encrypted file inside the app's own sandbox container on your Mac. Nothing is written anywhere else, and nothing leaves the machine. See the privacy policy.

Is it open source?

No — but the full design document is published, including the threat model, the cryptographic choices and the trade-offs behind them. "Trust me" isn't an argument you can make about a tool that holds credentials.

Getting help

Report a bug or ask a question:
github.com/rbongard/airlock-scratchpad-support/issues

Airlock Scratchpad is made by one person. Issues are read and answered, though not always quickly.

Never include a real credential in a bug report. If a secret is involved, describe its shape — "a 40-character hex string", "a PEM block" — rather than pasting it. The Scrub button exists for exactly this.
