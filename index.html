AirlockScratchpad

A secure scratchpad for the developer secrets you're working with right now — one that encrypts them, and forgets them on purpose.

Airlock Scratchpad is not a password manager. Anything that has to outlive the work you're doing today belongs in a real vault — 1Password, Bitwarden, HashiCorp Vault, AWS Secrets Manager. This is the layer above that: somewhere to put the keys and tokens you're actively using, instead of a scratch file.

Getting started

1. Set up the vault

On first launch you create a vault. It's protected by a key held in this Mac's Secure Enclave, unlocked with Touch ID — or with your login password on a Mac that has no Touch ID.

2. Capture a secret

Copy a key from wherever it lives, then press ⌘⇧V. The app works out what it is — a GitHub token, an AWS key, a certificate, a database URL — and opens the matching template with the fields already filled in.

Not ⌘V: that belongs to the system's paste, and taking it would make it impossible to paste into any field in the app itself.

To capture without switching to Airlock first, turn on ⌥⌘V under Settings → Capture. It works from any app.

3. Add a recovery code

Settings → Credentials → Generate a recovery code. Print it or write it down. This is the only thing that opens your vault if the Mac is lost, and it is shown exactly once.

Questions

I closed the window and now I can't get it back.

Closing the window locks the vault and leaves Airlock running in the menu bar — a window you can't see isn't one you're watching. There are three ways back: Window → Airlock Scratchpad, the padlock icon in the menu bar, or the Dock icon.

The padlock tells you the state without opening anything: the shackle is closed when the vault is locked, open when it isn't.

My secret disappeared. Where did it go?

It expired. Everything in Airlock has a deadline — three days by default — because a copy of a secret is not a secret's home. You can change the default in Settings, change it on any individual item, or turn on the Recycle Bin so expired items go there instead of being destroyed.

Why does it ask for Touch ID twice?

Unlocking shows you what you have — names, types, deadlines. Seeing or copying an actual secret asks again. Being in the app is not the same as being allowed to see a credential. After the second unlock there's a grace period, so you won't be prompted repeatedly, but you still press Reveal on each secret you want to see.

I lost my Mac. Can I get my vault back?

Only if you set up a recovery code or a password backup. The Secure Enclave key is bound to that specific Mac and cannot be exported, copied or recovered — not by you, and not by anyone else. There is no server, no account and no reset link.

That's the security model working as designed, and it's why the recovery code exists. Set one up before you need it.

Can Airlock generate a secret for me?

Yes. Press ⌘N, pick a type, then Generate a value: passwords, passphrases, hex and base64 tokens, UUIDs, and the values particular frameworks expect — a Django SECRET_KEY, a Rails secret_key_base, a JWT signing secret, NEXTAUTH_SECRET, a Flask SECRET_KEY, an AES-256 key. Each shows its strength in bits.

The value is encrypted, named and expiring from the moment it exists, rather than sitting in a terminal buffer until something scrolls it away.

The SSH key it generated has no passphrase.

That's correct, and the item says so. Airlock can't add one: OpenSSH protects private keys with a bcrypt key-derivation function that macOS doesn't provide, and taking cryptography from a third party to get it would cost more than it buys.

Copy as… → Add a passphrase gives you the exact ssh-keygen -p command to run once the key is on disk. The same warning appears on any unprotected SSH key in your vault, including ones you pasted in rather than generated.

Keys for CI or a deploy target usually should have no passphrase, since automation can't type one. The warning is there to make that a decision rather than an oversight.

What are stacks?

A stack lists the variables a piece of work usually needs. Select a project without selecting an item, choose the stacks it uses — PostgreSQL, AWS, Stripe, SMTP, Django, Next.js — and each variable is listed with what it's for and whether you have it yet.

Choosing a stack creates nothing. It's a list of what to look for, not empty items waiting to be filled, so turning one on or off never touches a secret. Entries tick themselves when a matching value arrives, however it arrives — including a .env import — and go back to not set when one expires. That last part is expiry doing its job, not the checklist losing track.

Does it sync between my Macs?

No. There's no sync, no iCloud, no account and no network code of any kind. A secret you need on two machines belongs in a real vault with proper access control.

Can I share a secret with my team?

No, and deliberately so. Shared credentials need access control and an audit trail; building half of that would be worse than not building it, because it invites a use it can't safely support.

The Scrub button didn't find my secret.

Scrubbing runs in two passes. First it removes every secret your vault holds that appears in the text, by exact match — so an in-house token format nothing could have guessed is still caught, as long as you've stored it. Where the item has an export variable, the placeholder is ${THAT_NAME}, so the text still says what was there.

Then shape rules run for anything your vault has never seen: recognisable vendor tokens, JSON web tokens, passwords inside connection strings, and named assignments that look like credentials. That second pass is deliberately cautious — a scrubber that mangles ordinary log lines is one you'd turn off — so a credential you've never stored, in a format it doesn't recognise, can still get through.

Always read the result before you send it.

How do I get a secret out in the form I actually need?

The Copy button is a menu. Depending on the type it offers a connection URI, a ready-to-run psql or mysql command, a JDBC URL, a .env block, an Authorization: header, a curl invocation, an ssh -i command, a public key line, or a PEM bundle — plus a shell export quoted correctly for bash/zsh, fish or PowerShell.

The database commands pass the password through the environment rather than the command line, because arguments are visible to every process on the machine and land in your shell history.

Copy Redacted is also there, and is the one entry that never asks for authentication — it discloses nothing, so you can say which key you mean in a ticket without handing over the key.

What are the cheat sheets?

Help → Cheat Sheets has one-page references on handling credentials: secrets in Docker, secrets in Kubernetes, secrets in the shell, and SSH keys and agents. They're about where secrets leak and what to do instead — not general command reference.

Read one in place, copy it, or add it to your Documents, where it becomes an ordinary document you can edit and delete. Restore Original puts the shipped text back if you want it, and tells you what that discards first.

Where is my data stored?

One encrypted file inside the app's own sandbox container on your Mac. Nothing is written anywhere else, and nothing leaves the machine. See the privacy policy.

Is it open source?

No — but the design and security document is published in full: the threat model, the cryptography, the trade-offs behind it, and what none of it protects you from. "Trust me" isn't an argument you can make about a tool that holds credentials.

It also lists the commands to check the main claims yourself — that the app requests no network access, and links no third-party code.

Getting help

Report a bug or ask a question:
github.com/rbongard/airlock-scratchpad-support/issues

Airlock Scratchpad is made by one person. Issues are read and answered, though not always quickly.

Never include a real credential in a bug report. If a secret is involved, describe its shape — "a 40-character hex string", "a PEM block" — rather than pasting it. The Scrub button exists for exactly this.
